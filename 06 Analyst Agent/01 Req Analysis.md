docstring 은 'https://finance.naver.com/news/mainnews.naver' 의 news 를 crawling 하여 '시장의 regime' 을 판단하고 '종목 추천'을 위해 만든 cli 실행 program 입니다.
지금부터 docstring 에 있는 cli 를 사용하여 'Analyst Agent'를 설계하려 합니다. 내용을 충분히 이해하고, 정의 가능한 'Analyst Agent' 의 요구 사항을 정리 해 주세요.


`docstring` 내용 기준으로 보면, 지금 시스템은 이미

* `run_crawler.sh` / `HourlyJob().run_once()` 로 **네이버 금융 주요뉴스 수집 + 분석 + DB 적재**
* `query_db.sh` / `list_news.sh` 로 **DB 조회 (news / analysis / symbols / recommendations / regime / all)**

까지는 완전히 갖춰진 상태입니다.

이제 이 위에 올라가는 **“Analyst Agent”**의 요구사항을 정리해볼게요.
(여기서는 *요구사항 정의*에만 집중하고, 구현/코드/프롬프트는 나중 단계로 미룹니다.)

## 1. 시스템 컨텍스트 & 전제

1. **데이터 소스**

   * `https://finance.naver.com/news/mainnews.naver` 에서 1시간마다 크롤링.
   * `HourlyJob` / `run_crawler.sh` 실행 시:

     * 최신 뉴스 수집
     * 감성/리스크 분석
     * 종목 매핑
     * 종목 추천 (recommendations)
     * 시장 regime 기록 (regime history)
     * 이를 모두 SQLite DB에 저장.

2. **DB 조회 채널**

   * `query_db.sh`:

     * `news`              – 최근 뉴스 기사
     * `analysis`          – sentiment/risk 분석 통계
     * `symbols`           – news ↔ symbol 맵핑
     * `recommendations`   – 종목 추천
     * `regime`            – 시장 regime 히스토리
     * `all`               – 전부 묶어서 조회
   * `list_news.sh` – 단순 최신 뉴스 리스트.
   * 옵션:

     * `--hours N`, `--limit N` 등으로 시간/개수 제어.

3. **Analyst Agent 위치**

   * LLM 기반 “애널리스트 역할”을 하는 상위 레이어.
   * 직접 DB를 만지지 않고, **기존 CLI/파이썬 모듈을 도구로 사용**해 정보 읽기.
   * 사용자는 자연어(한글/영어)로 질문 → Agent가 DB/CLI 결과를 조합해 답변.

## 2. Analyst Agent의 상위 목표

1. **시장 Regime 브리핑**

   * 최근 N시간(기본 24시간) 뉴스 기반으로:

     * 현재 시장 regime (예: risk-on, risk-off, 변동성 확대 등)
     * 변화 추세 (어제 vs 오늘, 지난 3일 등)
     * Regime을 설명하는 대표 뉴스/섹터/이슈 요약.

2. **종목 추천 리뷰 & 설명**

   * DB에 쌓인 `recommendations` 기준:

     * “오늘의 매수 후보” 목록 정리.
     * 각 종목에 대해:

       * 왜 후보인지 (sentiment, impact, risk 플래그 등)
       * 관련 핵심 뉴스/테마 요약.
       * 리스크 요인 & 주의사항 설명.

3. **뉴스 중심 탐색**

   * 사용자 질문:

     * “최근 24시간 반도체 관련 악재 뉴스 요약해줘”
     * “KOSPI 전체 sentiment는 어때?”
   * Agent:

     * `query_db.sh news/analysis` 를 시간/키워드 필터로 호출하거나,
     * 필요한 경우 `all` 모드로 가져와 후처리.
     * 상위 N개 뉴스/섹터/테마 단위로 정리해서 설명.

4. **종목 중심 분석**

   * 사용자 질문:

     * “삼성전자(005930) 최근 뉴스와 감성/리스크 요약”
     * “오늘 추천 리스트에 있는 종목들의 비교”
   * Agent:

     * `symbols + news + analysis + recommendations`를 결합해,
     * 해당 종목의 최근 뉴스/감성/리스크/추천 여부를 종합 설명.

5. **전략/리스크 관점에서의 코멘트**

   * Regime과 종목 추천을 보고:

     * “지금은 레버리지 확대보다 축소가 적합한지?”
     * “섹터별로 어디가 상대적으로 안전/위험한지?”
   * 단, **투자 자문이 아니라 정보 요약 + 패턴 설명** 수준으로 제한.

6. **파이프라인 상태 모니터링 (간단한 헬스체크)**

   * 최근 crawl 시간/뉴스 수/분석 건수 등을 통해:

     * “데이터가 최신인지?”
     * “크롤링/분석 파이프라인이 정상적으로 돌고 있는지?”
   * 예: “마지막 실행이 3시간 전입니다. 지금 한 번 더 크롤하려면 run_crawler.sh 실행이 필요합니다.” 같은 힌트.

## 3. 외부 인터페이스 요구사항

### 3.1 사용자 인터페이스

1. **입력 형태**

   * 자연어 텍스트 (한글 우선, 영어 지원).
   * 예:

     * “오늘 시장 분위기(Regime) 요약해줘”
     * “지난 48시간 동안 매수 후보 상위 5개 종목과 이유”
     * “2차전지 관련 악재 뉴스 정리해줘”
     * “최근 3일간 추천 종목의 성과 요약해줘” (나중에 가격 데이터 붙이면 확장).

2. **출력 형태**

   * 사람이 읽기 쉬운 natural language 보고서 스타일:

     * 헤더(요약) → 섹션(시장/섹터/종목) → bullet 설명.
   * 필요시 테이블/리스트:

     * 종목/score/sentiment/regime/리스크 플래그 등의 정리.

3. **언어/톤**

   * 금융 애널리스트 스타일의 간결한 한글 설명.
   * 과도한 추측/확신은 지양, 근거 기반 설명.
   * 투자 조언 아님(면책 멘션 포함) – *“참고 정보일 뿐, 투자 책임은 사용자에게 있음”*.

---

### 3.2 내부 툴/CLI 인터페이스

Analyst Agent는 다음 명령들을 **툴 호출**처럼 사용해야 합니다.

1. **Crawler 트리거 (선택)**

   * `./run_crawler.sh` 또는 `HourlyJob().run_once()` 를 통한 크롤링.
   * 요구사항:

     * 사용자가 “지금 최신 뉴스까지 반영해줘”라고 명시 요청할 때만 실행 (rate-limit 고려).
     * 기본 동작은 **이미 수집되어있는 DB를 사용**.

2. **DB 조회 – query_db.sh**

   * **news**:

     * `./query_db.sh news --hours H --limit N`
     * 결과: 최근 H시간 뉴스 목록 (제목, 시간, 종목 매핑 여부 등).
   * **analysis**:

     * `./query_db.sh analysis --hours H`
     * 결과: sentiment/risk 통계 (평균 감성, 리스크 비율 등).
   * **symbols**:

     * `./query_db.sh symbols`
     * 결과: 뉴스 ↔ 종목 맵핑 내용.
   * **recommendations**:

     * `./query_db.sh recommendations --limit N`
     * 결과: 추천 종목 목록 + score/관련 지표.
   * **regime**:

     * `./query_db.sh regime --limit N`
     * 결과: 시장 regime 히스토리(시간, 라벨, confidence, 설명 등).
   * **all**:

     * `./query_db.sh all --hours H --limit N`
     * 필요 시 한 번에 전체 데이터를 가져와 Agent 내부에서 후처리.

3. **단순 뉴스 리스트 – list_news.sh**

   * 가장 간단한 최신 뉴스 확인용.
   * 대표 기사 몇 개만 빠르게 훑고 싶을 때 사용.

4. **성능/캐싱**

   * 동일 질문 반복 시, 직전 `query_db` 결과를 일정 시간 캐싱해 재사용.
   * `--hours`, `--limit` 파라미터는 Agent가 질문 맥락에 따라 동적으로 설정:

     * “지난 3일” → `--hours 72`
     * “오늘” → 장문화 기준 `--hours 24` or 시간 기반 변환.

## 4. 기능 요구사항 (Functional Requirements)

### 4.1 Regime 분석 기능

1. **현재 Regime 요약**

   * 최근 N시간의 `regime` 기록을 읽고:

     * 가장 최신 regime 라벨과 confidence 제시.
     * 최근 몇 번의 regime 변화(전환 시점)도 요약.

2. **Regime 근거 설명**

   * 최신 regime 스냅샷과 연관된:

     * 상위 뉴스(impact 높은 기사들)
     * sentiment 비율
     * 주요 리스크 플래그(예: 규제, 매크로, 신용)
   * 를 근거로 “왜 이 regime이라고 보는지” 설명.

3. **Regime 트렌드 관찰**

   * 최근 24~72시간 regime 히스토리를 읽어:

     * “risk-on에서 점점 중립으로 이동 중”
     * “risk-off 상태가 3회 연속 유지”
   * 같은 추세를 자연어로 표현.

---

### 4.2 종목 추천 분석 기능

1. **최신 추천 종목 리스트**

   * `./query_db.sh recommendations --limit N` 결과를 해석:

     * 종목코드, 스코어, 생성 시각, 관련 sentiment/impact.
   * 상위 N개 종목(기본 5~10개)을 정렬해 요약.

2. **각 종목별 애널리스트 코멘트**

   * DB에 이미 분석된 지표(감성, 리스크, 뉴스 개수 등)를 기반으로:

     * “최근 뉴스 감성은 +0.35로 긍정적이며, 규제 리스크는 낮음”
     * “한 기사에서 실적 서프라이즈가 언급됨” 등.
   * 필요 시 대표 뉴스 2~3개 제목/내용 요약 첨부.

3. **리스크 관점 필터링**

   * 사용자 요청: “High risk는 제외해줘”, “규제 리스크 높은 종목만 보여줘”
   * Agent:

     * `analysis` / `recommendations` 데이터를 조합해 필터링한 리스트 생성.

---

### 4.3 뉴스/섹터/테마 분석 기능

1. **뉴스 밀도 & 감성 요약**

   * 시간창(예: 24시간) 기준:

     * 뉴스 개수, 긍/부정 뉴스 비율.
   * 섹터/테마별 대표 키워드 분석 (DB에 있거나 LLM기반 태깅).

2. **키워드/섹터 기반 질의**

   * “2차전지/AI/반도체 관련 뉴스 요약”
   * Agent:

     * `news` + (가능하면 `symbols`/테마정보) 조합해 해당 키워드 관련 기사 추출.
     * 상위몇 개 기사 요약 + 공통 패턴 설명.

---

### 4.4 종목 중심 리서치 기능

1. **단일 종목 리포트**

   * 입력: 종목코드나 이름 (예: “005930” 또는 “삼성전자”).
   * Agent:

     * 해당 종목과 연결된 뉴스(`symbols` + `news`) 조회.
     * 각 기사 감성/리스크(`analysis`) 종합.
     * 최근 추천 여부(`recommendations`) 확인.
   * 출력:

     * 최근 뉴스 요약
     * 종합 sentiment/risk 요약
     * 추천 여부 및 이유 (있다면)
     * Regime과의 정합성 코멘트 (예: risk-off인데도 이 종목만 긍정적 등).

2. **종목 비교**

   * “추천 상위 3개 종목 비교해줘”
   * 각 종목에 대해 동일 지표들(감성/리스크/뉴스 개수)을 표/텍스트로 비교.

## 5. LLM/에이전트 관점 요구사항

1. **툴 사용 전략**

   * Analyst Agent는 다음을 “도구(tool)”로 인식:

     * `run_crawler.sh` (데이터 갱신)
     * `query_db.sh` (모든 분석/조회용)
     * `list_news.sh` (단순 최신 뉴스 확인용)
   * 각 도구의 **입력 파라미터 (subcommand, --hours, --limit)** 를 잘 설계해 호출.
   * CLI 결과(텍스트/JSON)는 Agent 내부 로직에서 파싱 후 구조화해 사용.

2. **추론 & 요약 전략**

   * DB/CLI 결과를 단순 나열이 아니라:

     * 중요한 것과 덜 중요한 것의 구분,
     * 방향성(risk-on/off), 강도, 섹터 간 대비,
     * 종목 간 상대 비교
   * 를 중심으로 정리.

3. **안전/책임**

   * 답변에 명시:

     * “투자 권유가 아니라 정보 요약/분석용임”
     * “실제 매매 전에는 반드시 별도 검토 필요”
   * 극단적 확신 표현 (예: “무조건 오른다/내린다”) 피하기.

4. **대화 상태 관리**

   * 대화 흐름에서:

     * 사용자가 이전에 언급한 종목, 시간 범위, 관심 섹터 기억.
   * 예:

     * 유저: “삼성전자 최근 뉴스 어때?”
     * → Agent 분석 후
     * 유저: “그럼 현대차는?” → 직전 컨텍스트(시간창, Regime) 재사용.

## 6. 비기능 요구사항 (Non-functional)

1. **성능/최신성**

   * Regime/추천 분석에 사용하는 데이터는:

     * **기본적으로 최근 24시간** 기준.
     * 정밀 분석 요구 시 `--hours` 튜닝 가능.
   * 과도한 크롤링/쿼리를 피하기 위해:

     * 동일 질의에 대한 결과는 일정 시간(예: 수 분) 캐싱.

2. **확장성**

   * 이후 KOSPI/KOSDAQ 종목이 늘거나
   * 뉴스량이 폭증해도:

     * `query_db` 옵션 (`--hours`, `--limit`) 로 데이터량 제어.
     * 에이전트는 상위 N개만 골라 요약.

3. **테스트 가능성**

   * `python -m pytest tests/ -v` 를 통해:

     * Analyst Agent의 툴 호출 로직/파싱 로직/요약 텍스트 생성 로직을 unit test 가능하도록 설계.
   * Agent는 테스트 환경에서도:

     * 실제 크롤에 의존하지 않고, 샘플 DB/샘플 CLI 출력으로 동작 가능해야 함.

## 7. 요구사항 요약

* **입력**: 사용자의 자연어 질의(시장/섹터/종목/추천/리스크 관련).
* **도구**: `run_crawler.sh`, `query_db.sh (news/analysis/symbols/recommendations/regime/all)`, `list_news.sh`.
* **핵심 기능**:

  * 시장 Regime 요약 & 트렌드 설명.
  * 종목 추천 리스트 리뷰 및 근거 설명.
  * 뉴스/섹터/테마 기반 요약 및 리스크 분석.
  * 종목별 뉴스/감성/리스크/추천 상태 종합 리포트.
  * 간단한 파이프라인 헬스체크(데이터 최신성).
* **제약**:

  * DB는 read-only.
  * 크롤링은 필요 시/요청 시에만 발생 (rate-limit 고려).
  * 투자 자문이 아닌 **정보 분석 에이전트** 역할.

이 요구사항을 바탕으로, 다음 단계에서는:
